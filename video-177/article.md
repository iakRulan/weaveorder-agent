## 1. 行业背景与痛点

- 企业 AI 多停留在"单点试用"：文案生成、知识问答、图像创作，尚未嵌入生产/经营/管理核心流程。
- 三层困难：**系统难连接**（数据分散在多张表）、**流程难闭环**（取数→清洗→统计→核对→成文多个断点）、**价值难量化**（结果是否可信、效率提升多少缺可验证口径）。
- 赛题原文要求：完成任务理解、数据处理、系统调用、流程协同和结果输出；对接至少 2 个现有业务系统或工具；提交人工基线数据与智能体运行数据对比。

## 2. 场景与数据

- 场景：连锁零售企业经营分析。
- 数据集：公开的 Tableau Superstore 零售数据集。
  - **9,994 笔**真实订单，**21 个字段**（订单/日期/区域/品类/子品类/销售额/数量/折扣/利润）。
  - 退货清单 **296 单**；区域负责人 **4 人**（Anna Andreadi/West、Chuck Magee/East、Kelly Williams/Central、Cassandra Brandow/South）。
  - 时间跨度 2014–2017，四个年度。
- 业务问题：**哪些子品类在亏损，为什么？**

## 4. 方案：五段闭环

1. **任务输入**：自然语言分析需求。
2. **信息理解**：大模型解析为结构化分析要点（意图/焦点/维度/指标）。实测识别四类意图：profit_diagnosis / trend / region / category_overview。
3. **流程判断**：按意图生成确定性分析 DAG（可复现、可审计）。
4. **系统调用**：工具注册表统一校验参数、风险分级、超时控制；同层步骤并行。
5. **结果输出**：报告 + 确定性校验器独立重算每个指标，不一致即拦截。

**系统对接（三类）**：
- 数据服务（SQLite 引擎）：装载 orders/returns/people 三表，执行只读 SELECT。
- 报表服务：从 SQL 结果解析指标引用，生成 Markdown 报告与明细表。
- 大模型推理服务：自然语言需求理解。

**数据流转**：三张表入库 → 5 类 SQL 聚合（子品类盈亏 / 折扣档位 / 跨表退货率 / 品类汇总 / 整体指标）→ 报告指标引用解析（不手抄数字）→ 校验器独立重算。

## 7. 质量保障：同一错误注入实验

- 注入方式：把报告关键指标（利润率）算错一半。
- **校验器开启**：报告被拦截、不发布（状态 failed），并给出原因「报告值 6.235 与数据源重算值 12.47 不一致，已拦截」。
- **校验器关闭**：错误数字直接发布（+6.2% vs 正确值 +12.5%）。
- 人工流程若要达到同等保障，需额外增加交叉核对步骤（约 +10 分钟）。
