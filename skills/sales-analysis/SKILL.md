# Sales Analysis

把一句分析需求变成数字可回查的经营报告，而不是一段“大概下降了”的描述。

## When to use

- 用户给一份 CSV/表格，要求“分析”“找原因”“看走势”“出报告”
- 需要环比/同比、分区/分品类的归因结论
- 报告数字需要经得起对账

## Workflow

1. **摸数据**：调用 `file_read`，确认字段、行数、缺失值；缺失值必须在报告中披露。
2. **聚合**：调用 `sql_query`（只读 SELECT），按“大区 × 月度”“品类 × 月度”“全国月度”三张切面聚合。
3. **定指标**：每个指标声明 `{当期, 基期, 口径}`；环比 = (当期−基期)/基期。
4. **渲染**：调用 `report_render`，指标以引用方式从 SQL 结果取值，**不要手抄数字**。
5. **校验**：报告中的每个数字都要能用同一套查找逻辑从 SQL 结果独立重算出来；重算不一致 = 报告不可发布。
6. **归因**：找绝对降幅最大的切面作为主驱动，同时说明其他切面的对冲效应。

## Guardrails

- 数据源不覆盖的区域/品类：明确报告“不覆盖”，不要用相邻数据外推。
- 缺失值只披露、不插补；插补会改变归因结论。
- 不要心算百分比；让 `report_render` 从引用中计算。
- 只读分析：不修改数据文件，不执行非 SELECT 语句。
