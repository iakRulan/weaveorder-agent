# Itinerary Audit

对一份行程/差旅交付报告做独立核验，而不是默认它正确。所有结论必须能回指到报告原文或工具返回。

## When to use

- 用户提供一份行程单、费用报告或 `report.md`，要求“核对/审计/检查”
- 需要在预订（付款/出票）前确认报告数字与政策一致
- 评审或对账场景：需要给出可追溯的核验意见

## Workflow

1. **重算费用**：总费用 ?= 去程票价 + 返程票价 + 酒店单价 × 晚数 + 市内交通。若有 `compute_trip_cost` 工具，用工具算，不要心算。
2. **核对预算**：总费用 ≤ 预算；若超预算，报告必须显式标注“降级”并有人工审批记录，而不是静默通过。
3. **核对政策**：单程机票 ≤ 舱位上限、酒店 ≤ 目的地城市上限、无红眼航班（00:00–06:00 起飞）、酒店距客户地点距离是否已披露。
4. **核对一致性**：行程单里出现的航班号/酒店名/价格，与检索工具返回的 `best` 选项一致；总额与费用工具输出一致。
5. **核对审批**：预订类动作必须有 `request_approval` 记录（批准/拒绝/超时）；缺少审批 = 高风险发现。
6. **输出意见**：按“发现 → 证据（引用原文/数值） → 建议”三段式，分为 blocker / warning / note 三级。

## Guardrails

- 不要因为报告“看起来完整”就跳过重算；数字一致性是最低底线。
- 找不到证据的结论要标注“无法核验”，不要替报告补证据。
- 审计只读：不要替用户改订单、重订或发通知。
