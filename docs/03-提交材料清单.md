# 提交材料清单

> 以官方赛题手册为准；下面是按“代码实现方案 + 技术文档 + ≤5 分钟视频”准备的通用清单。

## 1. 代码包

提交前检查：

- [ ] 公开 GitHub 仓库可访问，或压缩包结构清晰
- [ ] `README.md` 写清：项目一句话、架构图、快速开始、目录、评测命令
- [ ] `requirements.txt` 能一次装好；Python 3.11+
- [ ] 提供 `.env.example`，不提交 `.env`
- [ ] `runs/`、`__pycache__/`、`.venv/` 已清理或加入 `.gitignore`
- [ ] 无 API Key、无真实公司/客户数据
- [ ] 无大文件（视频不进代码包，放链接）
- [ ] License（MIT 即可）

检查密钥：

```bash
git grep -n -i -E "sk-|api[_-]?key|password|secret" || true
```

## 2. 技术文档 PDF

建议 8–12 页，结构：

| 页 | 内容 |
|---|---|
| 1 | 标题、团队、一句话摘要、关键词 |
| 2 | 问题定义：为什么通用聊天机器人不够；赛题三项能力拆解 |
| 3 | 总体架构图（Planner–Scheduler–Executor–Verifier–Replanner） |
| 4 | 关键数据结构：Plan/Step/Trace；DAG 与引用解析 |
| 5 | 规划算法：LLM 规划 + Schema 校验 + 规则回退 |
| 6 | 校验与修复：三层 Verifier；预算/政策/数值一致性；修复策略 |
| 7 | 工具层与安全：Tool Registry、参数校验、沙箱、风险分级审批 |
| 8 | 场景一：差旅编排（含截图与 Trace 片段） |
| 9 | 场景二：经营分析（含图表与数字校验） |
| 10 | 评测：任务集、指标、基线、消融结果 |
| 11 | 局限与未来工作；与同类方案对比 |
| 12 | 复现步骤、链接、致谢 |

写作要求：

- 不要写成“我们做了很多功能”的流水账；围绕**编排层为什么必要**展开。
- 每个技术点配一张图或一段 Trace/代码，不要纯文字。
- 评测部分给出数字和对比，不要只写“效果良好”。
- 明确写出失败案例与修复过程，这比只展示成功更有说服力。

## 3. 演示视频（≤5 分钟）

结构建议：

| 时间 | 内容 |
|---|---|
| 0:00–0:30 | 一句话问题：差旅安排要查政策、比价、算预算、走审批，现有聊天机器人只会聊天 |
| 0:30–1:00 | 展示输入一句话目标，系统生成计划 DAG |
| 1:00–1:50 | 正常路径：政策检索 → 航班 → 酒店 → 费用 → 行程草案 |
| 1:50–2:40 | 失败恢复：注入“无航班/超预算”，展示 Verifier 失败 → Replanner → 成功 |
| 2:40–3:20 | 人工审批闸门：预订前暂停，展示批准/拒绝 |
| 3:20–4:10 | Trace 回放：每个结论能反查到工具调用；报告数字可校验 |
| 4:10–4:40 | 第二场景（经营分析）快速展示通用性 |
| 4:40–5:00 | 评测结果与总结 |

录制要求：

- 至少 3 分钟是真实运行，不要全程 PPT。
- 字体调大，终端/网页缩放 125%–150%。
- 先写旁白稿，再录屏；不要边想边说。
- 视频上传 B 站/YouTube/阿里云盘，设为公开可访问；把链接写进 PDF 和提交包。
