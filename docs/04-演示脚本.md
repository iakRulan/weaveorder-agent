# 5 分钟演示脚本

> 目标：让评委在 5 分钟内看懂“编排层到底做了什么”，而不是只看一个聊天界面。
> 录制前先按 README 跑通 `--mock`，再录有 Key 的版本。

## 0:00–0:30 问题

**画面**：一张简单的对比图/终端。

**旁白**：

> 企业差旅安排不是一个问答问题：要查政策、比价、算预算、校验合规、走审批，任何一步失败都要换方案。普通聊天机器人能给你一段建议，但不能保证这些步骤真的执行、真的合规、真的可追溯。我们做的是中间这层——任务编排。

## 0:30–1:00 一句话目标与计划

**操作**：

```bash
python agent.py --mock "帮我安排 2026-10-28 上海到深圳的客户拜访，10-30 返回，预算 3000 元，偏好早班机"
```

**画面**：终端输出计划步骤；切到 `runs/<时间>/plan.json` 展示 DAG。

**旁白**：

> 用户只给一句话。系统先解析出出发地、目的地、日期、预算，然后生成一个有依赖关系的计划：政策检索和航班/酒店搜索可以并行，费用计算依赖前两者，行程草案依赖全部结果，最后一步是预订审批。注意最后一步被标记为高风险，不会自动执行。

## 1:00–1:50 正常路径

**操作**：让程序继续跑完（或重新运行一次）。

**画面**：逐步输出 `check_policy`、`search_flights`、`search_hotels`、`calculator`、`draft_itinerary` 的结果摘要；最后展示 `report.md`。

**旁白**：

> 每一步都有工具名、参数、返回摘要和校验结论。政策检索给出依据，航班和酒店按价格排序，费用计算直接引用前两步的结果，而不是让模型心算。最后生成行程草案，包含交通、住宿、政策依据、费用和待确认项。

## 1:50–2:40 失败恢复

**操作**：

```bash
python agent.py --mock --inject-failure "帮我安排 2026-10-28 上海到深圳的客户拜访，10-30 返回，预算 3000 元"
```

**画面**：第一次航班搜索返回空 → 校验失败 → `replan` 事件 → 放宽价格上限后成功。

**旁白**：

> 我们故意把航班价格上限压到 800，第一次搜索没有结果。系统没有直接报错，而是记录失败原因，触发一次重规划：放宽价格上限，重新搜索，然后继续后面的步骤。这就是“编排”和“固定工作流”的区别——计划是活的。

## 2:40–3:20 人工审批

**操作**：不加 `--yes` 运行，程序在预订步骤暂停；输入 `n` 展示拒绝，再运行一次输入 `y` 展示批准。

**画面**：审批卡片：动作、工具、参数、金额。

**旁白**：

> 预订、付款、发送这类动作被标记为高风险。执行前系统暂停，把动作、参数和金额交给人工确认。拒绝不会让整个任务崩溃，而是记录为“未批准”，报告里仍然保留已经完成的行程草案。可控性不是事后日志，而是执行前的闸门。

## 3:20–4:10 Trace 回放

**操作**：

```bash
cat runs/<时间>/trace.jsonl
```

**画面**：逐条高亮 `tool_call`、`tool_result`、`verify`、`replan`、`approval`。

**旁白**：

> 报告里的每一个结论都能反查到具体工具调用：哪一步、什么参数、返回了什么、校验是否通过、有没有重试。评委如果怀疑“这个价格是编的”，可以直接查 Trace。这就是可审计。

## 4:10–4:40 第二场景（待实现）

**画面**：经营分析报告：CSV → SQL 聚合 → 图表 → 数字校验 → 报告。

**旁白**：

> 同一套引擎换一组工具，就能做经营分析：读 CSV、跑 SQL、画图、校验报告里的数字是否和查询结果一致。差旅是流程编排，分析是数据编排，引擎不变。

> 如果视频录制时第二场景还没完成，这一段改成“架构复用说明”，用架构图讲清楚，不要造假。

## 4:40–5:00 评测与总结

**画面**：评测结果表：Task Success、Constraint Satisfaction、Recovery Rate、Token/任务。

**旁白**：

> 我们在 12 个任务上对比了单次调用、ReAct 和固定工作流。完整引擎在约束满足率和失败恢复率上更高，代价是更多工具调用和略高的延迟。我们的结论不是“模型更强”，而是“编排层让同一个模型更可靠”。

**收尾**：

> 织序：让 agent 不只是会说，而是能把事做完、做对、做得可追溯。

## 录制小贴士

- 先录屏、后配音；旁白按上面的段落分段录，方便重录。
- 终端字号调到 18–20，深色背景；关键行用高亮或 `jq` 过滤。
- 失败注入那一段不要剪掉中间过程，评委要看的是恢复链路。
- 视频最后留 3 秒项目名/仓库地址，不要停在终端闪烁光标上。
